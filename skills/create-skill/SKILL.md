# 创建技能

## 步骤

1. **明确目标**:确认要固化的能力是什么(一句话描述)
2. **访谈边界**(向用户确认,一次问清):
   - 触发场景:什么任务/关键词时应该使用这个技能?(决定 description)
   - 输入/输出:接收什么、产出什么
   - 关键注意事项:容易出错/必须遵守的点
   - 粒度:单个能力 → 原子技能;多步骤流程 → 工作流技能
3. **生成 SKILL.md**:按下方模板;生成后**自己检查**格式完整
4. **校验**:运行 skills_manager.validate_skill(name) 确认(ok=True)
5. **保存**:write_file 写入 `skills/<name>/SKILL.md`(等用户确认写入)

## SKILL.md 格式模板

```yaml
---
name: <kebab-case 技能名>
description: <一句话说明 + 触发时机(什么场景/关键词使用),决定索引命中>
type: atomic            # 或 workflow
# workflow 类型附加:
steps:
  - <引用的原子技能名>
---

# <技能标题>

## 步骤

1. ...
2. ...

## 注意事项

- ...
```

## 原子 vs 工作流判断

- 单能力、无子步骤 → **atomic**(如"整理笔记")
- 多步骤流程 → **workflow**:steps 引用已有原子技能;
  若某个原子技能还不存在,**先创建它**,再创建工作流引用

## 注意事项

- `name` 用 kebab-case(小写字母 + 连字符),与目录名一致
- `description` 必须写清**触发时机**(技能索引只展示 description,
  LLM 靠它决定何时用这个技能)——"当用户 XX 时使用"句式最稳
- 正文结构:步骤(可执行清单)+ 注意事项(防坑)
- 工作流技能在编排说明中写明"每步执行前先 read_file 引用技能"
- 技能保存到 skills/ 自由区,git 管理可回退
