## B. 操作流程指南

### 步骤 1:启动
```
cd D:\Engineering\dummy
set DUMMY_AGENT_BASE_URL=https://api.deepseek.com
set DUMMY_COLOR=1
python main.py
```

### 步骤 2:制造错误率(触发 A1 报警)
连续让 agent 执行错误命令,例如:
```
用 terminal 执行一个不存在的命令，比如 definitely-not-a-command-xyz
```
重复 3-4 次(每次让它再跑一次不存在的命令)。
→ 观察第 4 轮后是否出现 ⚠️ 报警(A1-1),且只出现一次(A1-2)。

### 步骤 3:/improve 基本入口(A2)
```
/improve
/improve nonexistent
```
→ 分别看用法提示 / 无统计提示。

### 步骤 4:提案生成与展示(A3)
```
/improve terminal
```
→ 看提案展示(根因/改动清单/验证计划);**此时先不批准**,切到另一个终端跑
`git status` 确认没有文件被改动(A3-2 只读)。

### 步骤 5:拒绝路径(A5)
在批准提示处输入 `n` → 看"已拒绝"。

### 步骤 6:/p 打断(A6)
再次 `/improve terminal`,批准提示处输入 `/p` → 看打断取消,文件无改动。

### 步骤 7:批准路径(A4)—— 真实验证闭环
再次 `/improve terminal`,这次输入 `y`:
- 观察修改执行 + 验证门输出(✅ 修改成功 或 ⛔ 回退)
- 成功后:`git diff` 看实际改动;跑 `python -m pytest tests/ -q` 确认全绿(A4-3)
- 若回退:看 A7/A8

### 步骤 8:教训与记录(A8/A9)
```
/lessons
```
→ 若有回退,应有"自我改进修改失败"教训条目(A8-1);confirm/del 试一下。
检查 `logs/self-improve.jsonl`(A9-1;拒绝路径不写记录 A9-2)。

### 步骤 9:回归(A10)
跑一轮 /skills、/memories、正常对话;让 write_file 改个小文件看确认+diff 标色。

## C. 注意事项

1. **批准路径有真实副作用**:LLM 会真的改文件。验证门(语法/导入/pytest/启动)
   会兜底,改坏自动 git 回退——但盯着看更稳。
2. **git 工作区**:测试前建议 `git status` 干净,回退/对比更直观。
3. **错误样本**:每次 dispatch 只保留最近 3 条错误样本(提案分析的输入)。
4. **阈值**:错误数 ≥3 且错误率 >30% 才触发报警(I4-A);少于 3 次不会报。
