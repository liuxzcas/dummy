# 临时产物登记与清理（设计占位）

> 编写：2026-10-19
> 状态：**未实现**（用户明确"这个 feature 可以先不实现"）
> 已实现的部分：`pastes/*.txt`（输入侧粘贴文件）的轮末清理

---

## 一、用户的原话

> "在此基础上我想给 dummy 加一个纪律：在一轮 tool-calling 对话中所有为了任务产生的脚本，
> 都要记录在案并且在该轮对话结束时询问用户是否一键清除。最后这个 feature 可以先不实现。"

---

## 二、现状：已实现的半边

**输入侧**（`pastes/*.txt`）已经做了：

```
粘贴长文本 → input_layer 写文件并登记到 _round_files
    ↓
一轮对话结束 → core.chat() 的 finally 调用 _cleanup_round_temp_files()
    ↓
静默删除（不问用户）
```

**为什么输入侧可以"不问用户直接删"**：
```
· 它是输入层的中间产物，用户不关心它的去留
· 内容已经进了对话（模型读过/用户发过）
· 留着只会在 pastes/ 越积越多
```

---

## 三、未实现的另一边：工具产出的脚本

**用户要的是**：

```
一轮 tool-calling 中产生的东西（如模型写的临时 .py / .sh / 测试脚本）
    ↓
登记在案
    ↓
本轮结束时【询问用户】是否一键清除
```

**为什么这一边不能"静默删"**：

```
· 模型写的脚本可能是用户想要保留的成果（比如一个有用的工具）
· 也可能是纯中间产物（比如验证用的探针）
· 代码不知道意图 → 必须问
```

## 四、设计要点（待细化）

### 4.1 怎么"登记"

**候选方案**：

| 方案 | 做法 | 问题 |
|---|---|---|
| **A. 按工具调用追踪** | `write_file` / `terminal`（含重定向、heredoc）产生的新文件都记下 | ⚠️ `terminal` 里能创建文件的方式太多（重定向、`touch`、`python -c "open(...)"`），**追踪不全** |
| **B. 快照差集** | 一轮开始/结束各拍一次工作区文件快照，差集就是新产生的 | ✅ 能覆盖所有创建方式<br>⚠️ 代价：要遍历工作区（小项目可接受）<br>⚠️ 与"残留进程报告"里排除的方案类似（那里失败是因为要扫全系统进程，这里只扫工作区，量级不同） |
| **C. 工具自己申报** | 让 `write_file` 主动上报路径；`terminal` 靠事后探测 | ⚠️ 混合方案，仍然漏 |

**倾向 B**（工作区快照差集）—— 因为 dummy 的工作区不大，且能覆盖"模型用任何方式创建文件"。

**但要注意**：
```
· 排除 .git / __pycache__ / logs / pastes / session.db 等
· 用户自己也在这期间改文件 → 会混进来（无解，但要如实说明）
```

### 4.2 怎么"询问"

```
本轮结束 → 有新增文件 → 提示:
    本轮产生了 3 个新文件:
      · /tmp/probe.py
      · /tmp/verify.sh
      · test_scratch.py
    是否清除? [y=全部清除 / n=保留 / 编号=只删指定的]
```

**与现有交互的一致性**：dummy 已有的确认交互走 `_confirm_provider`（`core.py:1490`），可以复用。

### 4.3 与"输入侧清理"的区别

| | 输入侧（pastes） | 工具侧（脚本） |
|---|---|---|
| 用户是否关心 | 不关心 | **可能关心** |
| 处理方式 | 静默删 | **询问** |
| 为什么不同 | 内容已进对话 | 可能是成果 |
